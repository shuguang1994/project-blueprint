## issues/ — 日期戳问题台账

> 承接「一次性排查/审计产出的问题清单」，与 A~E 正式文档分离，避免临时清单污染正式文档编号体系。

| 要素 | 说明 |
|------|------|
| 用途 | 一次性排查、审计、专项检查产出的问题清单 |
| 命名 | `<主题>-<YYYYMMDD>.md`（日期戳），例：`<模块>-issues-<YYYYMMDD>.md`（YYYYMMDD 为真实日期） |
| 内容要素 | 问题编号（P0/P1/P2/P3 分级）+ 定位（`文件:行号`）+ 现象 + 建议方案 + 状态（未修复/已修复/不成立） |
| 生命周期 | 问题闭环后**移入 `docs/archive/`**，或合并进正式方案文档 |

## archive/ — 归档登记表

> 归档不是删除：`archive/` 下需有归档登记表（可放在 `docs/README.md` 的归档章节），记录每份归档文档的来源与原因。

登记表列：`文档名 | 原编号 | 归档原因`

- 归档原因必须写实（如「内容已被 XX 覆盖」「功能已实现、完成使命」「内容过时」），禁止留空
- 归档后**编号不得与主目录重复**；若刻意区分可在编号后加字母后缀（如 `B-16a`）

## .trae/specs/ — 规范驱动开发（spec 三件套）

> 与 `docs/` 平行、位于 `docs/` 之外的变更级工作区：一次变更一个目录。完整流程（六阶段准入门槛 / 三件套模板 / checklist 转门禁）见 `references/spec-driven.md`，Step 3.3 引用。

| 路径 | 说明 |
|------|------|
| `.trae/specs/README.md` | 六阶段流程与三件套用途说明 + change-id 命名规则 |
| `.trae/specs/<change-id>/` | 单次变更的三件套：`spec.md` / `tasks.md` / `checklist.md`（模板见 `references/spec-driven.md` 第四章） |
| `.trae/specs/archive/<change-id>/` | 变更验收后整体归档，保持相对结构不变 |

- **零固定表**：初始化只建 `README.md` 与 `archive/`，具体 `<change-id>/` 在变更启动时按需创建，不预设变更清单
- **命名**：`<change-id>` 动词开头 + kebab-case（如 `fix-coupon-oversell`）；同一 change-id 未完成时继续追加，不新建
- **IDE 差异**：Cursor 下目录为 `.cursor/specs/`；不支持 specs 的 IDE 则跳过（回落到 `references/ai-work-protocol.md` 的 7 步）
- **与 `docs/archive/` 的分工**：`.trae/specs/archive/` 归档**变更三件套**（过程留痕），`docs/archive/` 归档**正式文档**（内容资产），两者互不替代

**checklist 转门禁**：`checklist.md` 中可机检的验收点可转为门禁，登记进 `scripts/gates.json`，`source` 记为 `spec#<change-id>`（字段沿用门禁清单既有字段，口径见 `references/gates-templates.md` §一）。哪些 checklist 适合转门禁（准入门槛四问）、以及门禁随 spec 归档的生命周期，见 `references/spec-driven.md` 第五章。

## 文档契约

> **新增即达标 + 存量逐步补**：新增文档必须一次到位；存量不合格记 warning，不阻断流程。

**头部契约**：`docs/B`、`docs/C` 每篇文档头部须有一行元信息：`> 版本: … | 更新: … | 状态: …`

**编号唯一**：编号缺号须满足以下之一 ——
1. 在 `docs/archive/` 有同号归档文档；
2. 在索引中标注为「预留/未使用」。

**索引完整**：索引（`docs/README.md`）须覆盖全部非归档文档，且索引内的相对链接须指向真实文件。

**校验脚本**：`node scripts/docs-check.mjs`（提交前 + CI 均须通过，仅 error 阻断，warning 不阻断）。

## 生成规则

1. **按需生成**：按 SKILL.md Step 3.0 推断的业务类型选择对应文件
2. **每个文件初始内容仅一行**：`# [文件名]` + `> 待填写`
3. **分类目录下生成 README.md**：说明该分类的用途和维护指令
4. **archive/、issues/ 和 dev/ 只创建目录**（archive/ 可同时生成归档登记表），不放具体文件
5. **如果 docs/ 已存在**：只补充缺失的文件，不修改已有内容
6. **文件名中英双语**
7. **规模阈值**：`B-06-门禁与工作协议.md` 仅中大型项目按规模阈值生成，小型项目不生成

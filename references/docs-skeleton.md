# docs/ 目录骨架指南

> Skill `project-blueprint` Step 3 参考。每个目录下的文件均为占位符，待项目进展逐步填写。

---

## 目录结构总览

```
docs/
├── A/                          # 项目基准文档（PRD、架构、数据库、API）
├── B/                          # 开发运维文档（规范、部署、测试、Bug知识库）
├── C/                          # 知识沉淀文档（Code Wiki、架构详解、长期记忆）
├── D/                          # 方案设计文档
├── E/                          # 分析优化文档
├── archive/                    # 已归档历史文档
└── dev/                        # 开发中的方案文档
```

## 生成规则

1. **每个文件初始内容仅一行**：`# [文件名]` + `> 待填写`
2. **分类目录下生成 README.md**：说明该分类的用途和文件列表
3. **archive/ 和 dev/ 只创建目录**，不放文件
4. **如果 docs/ 已存在**：只补充缺失的文件，不修改已有内容

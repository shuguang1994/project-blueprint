# docs/ 目录骨架指南

> Skill `project-blueprint` Step 3 参考。**实际生成按业务类型动态裁剪**（见 SKILL.md Step 3.1），此处为完整的可选文件清单。

## 目录结构总览

```
docs/
├── A/                          # 项目基准文档（PRD、架构、数据库、API）
├── B/                          # 开发运维文档（规范、部署、测试、Bug知识库）
├── C/                          # 知识沉淀文档（Code Wiki、架构详解、长期记忆）
├── D/                          # 方案设计文档
├── E/                          # 分析优化文档
├── archive/                    # 已归档历史文档
└── dev/                        # 开发中的方案文档
```

## A/ — 项目基准文档

> 按业务类型选择：后端选 A-02+A-03，前端选 A-04，移动端选 A-05，全栈选全部。

| 文件 | 内容 | 何时填写 |
|------|------|---------|
| `A-01-PRD.md` | 产品需求文档 | 项目启动时（必选） |
| `A-02-技术架构.md` | 整体技术架构设计 | 后端/全栈项目，架构确定后 |
| `A-03-数据库设计.md` | ER 图、表结构、索引策略 | 有数据库时创建 |
| `A-04-前端架构.md` | 前端技术选型、组件架构 | 前端项目时创建 |
| `A-05-移动端架构.md` | 移动端技术选型、多端适配 | 移动端项目时创建 |

## 生成规则

1. **按需生成**：按 SKILL.md Step 3.0 推断的业务类型选择对应文件
2. **每个文件初始内容仅一行**：`# [文件名]` + `> 待填写`
3. **分类目录下生成 README.md**：说明该分类的用途和维护指令
4. **archive/ 和 dev/ 只创建目录**，不放文件
5. **如果 docs/ 已存在**：只补充缺失的文件，不修改已有内容
6. **文件名中英双语**

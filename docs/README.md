> 版本: v1.0 | 更新: 2026-09-14 | 状态: 生效

***

## 一、分类约定

| 分类 | 定位 | 维护时机 |
|------|------|---------|
| `docs/A/` | 项目基准（PRD / 架构 / 数据库设计） | 架构变更时同步更新 |
| `docs/B/` | 开发运维（开发规范 / 部署 / 测试 / BUG 知识库 / MCP 清单 / 门禁与工作协议） | 流程变更时同步，每次部署后检查 |
| `docs/C/` | 知识沉淀（CodeWiki / 架构详解 / 项目长期记忆） | 重大决策或修复典型 Bug 后更新 |
| `docs/D/` | 方案设计（方案 / 评估报告 / 发布说明） | 新方案确定或发版后补充 |
| `docs/E/` | 分析优化（耦合度分析 / 审计报告） | 定期审计时更新 |
| `docs/archive/` | 归档（已下线或被取代的文档，编号与主目录不重复） | 文档归档时登记 |
| `docs/dev/` | 开发过程产物（临时记录，不参与编号与状态头校验） | 按需 |

> 文档契约：`docs/` 下各系列文档须带状态头 `> 版本: … | 更新: … | 状态: …`；编号唯一，缺号须在 `docs/archive/` 有同号归档或在本索引标注预留；单篇 ≤ 600 行。

## 三、维护规则

1. **新增文档**：在对应分类目录建档 → 在本索引补一行（编号 + 链接）→ 跑校验脚本留证。
2. **编号唯一**：同一编号被多个非语言变体文件占用会被判为 `error`；中英双语用 `-EN.md` 后缀（视为同一编号的变体）。
3. **归档**：文档下线时移入 `docs/archive/`，编号不得与主目录重复（冲突记 `warning`），并在本索引移除或标注。
4. **校验命令**：

```bash
node references/docs-check.mjs     # 单跑文档一致性（种子门禁 docs-consistency）
node scripts/verify.mjs            # 门禁统一入口（本仓库 2 条门禁：docs-consistency + spec-drift）
```

> 退出码约定：`0` = 无 error（warning 不阻断）；`1` = 存在 error。

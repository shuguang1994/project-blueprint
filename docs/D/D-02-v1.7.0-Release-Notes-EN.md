# v1.7.0 Release Notes — Code Convention Closed-Loop Enhancement

> Release: 2026-08-14 | Version: v1.7.0 (minor, no breaking changes) | Upgrade: `npx skills update project-blueprint` or `dsh plugin --profile web add 'github:shuguang1994/project-blueprint'`

## 1. This Release in One Sentence

**Project initialization now moves from "convention skeleton only" to "real base coding conventions written into the project," with a three-tier AGENTS → B-01 → B-04 feedback loop so conventions keep evolving with real-world practice and AI stops repeating the same mistakes.**

## 2. Why This Update

Pre-v1.7.0 initialization had three real gaps:

| Gap | Impact |
|-----|--------|
| Only **component-level conventions** (e.g. NestJS/Vue-specific rules), no cross-cutting base conventions | Naming, error handling, logging, security, performance left to model improvisation — inconsistent style |
| `docs/B/B-01-开发规范.md` was a **one-line placeholder** | No actual coding conventions written after init |
| AI high-frequency mistakes only covered in fragments; bugs couldn't feed back into conventions | The model repeats the same errors; the convention system "is born but never grows" |

## 3. Core Updates

### 3.1 Three-Tier Code Convention System (AGENTS → B-01 → B-04)

```
L1  AGENTS.md Mandatory Conventions (core, ≤20 rules, read before every coding task)
       │ reference                      ↑ feedback
L2  docs/B/B-01-开发规范.md (detailed 8 chapters, on demand)
       │ reference                      ↑ feedback
L3  docs/B/B-04-BUG知识库.md (real bug accumulation, with "convention feedback" field)
```

- **L1**: Core rules for 5 categories (naming/error handling/logging/security/performance, ≤4 per category), with AI high-frequency mistake prevention rules injected first
- **L2**: B-01 upgraded from placeholder to **8 real chapters** (naming / directory structure / error handling / logging / security / performance / stack-specific / AI-mistake prevention list + convention maintenance)
- **L3**: B-04 template now includes "convention deficiency? / convention feedback" fields — when a bug root cause is a missing convention, it auto-feeds back into L1/L2

### 3.2 New Knowledge Base #1: Base Code Conventions Seed (code-conventions.md)

6 categories × language adaptation (TypeScript / Go / Python / Java / database), each with ✅/❌ rules + web search templates. Acts as a **deterministic baseline** (floor); model knowledge expands, web search covers unknown stacks (ceiling) — following the existing 3-tier design.

### 3.3 New Knowledge Base #2: AI Common Mistakes Prevention (ai-common-mistakes.md)

**The highest-priority special in this release.** 7 categories, 27 entries, each with six sections (AI mistake / consequence / ❌ wrong example / ✅ correct fix / linked KB entry / search template):

```
Dependencies/API · Data/Performance · Error handling · Security · Type/Language · Engineering · Git
Example: recalling TypeORM 0.2 API from memory → incompatible with 0.3 → ❌ demo + ✅ AppDataSource pattern
```

Step 2 injects matching prevention rules **by detected stack first**; uncovered mistakes trigger web search.

### 3.4 BUG → Convention Feedback Loop (Step 7 Enhancement)

When fixing a bug whose root cause is an **AI mistake**:

1. Check whether it hits the ai-common-mistakes list
2. **Hit** → strengthen the rule (mark occurrence count in B-01)
3. **Miss** → add a list entry + a B-01 rule + one ✅/❌ anti-recurrence rule in AGENTS.md

One fix = one convention evolution, preventing the model from repeating the same mistake at the source.

### 3.5 Project Progress & Documentation Health Check

Generated AGENTS.md injects a "Project Progress & Documentation Health Check" mechanism. The agent proactively checks doc lag at these milestones and reminds the user to maintain:

| Milestone | Check items |
|-----------|-------------|
| Feature complete | Module table / tech stack line / whether conventions need additions |
| Refactor complete | Architecture decision table / directory structure / coupling analysis |
| Pre-release | B-02 deployment guide / CI description / checklists |
| End of quarter | Project memory cleanup / B-04 archival / convention system review |

User says "check project progress" → agent outputs: recent progress + doc lag list + suggested maintenance items.

## 4. How to Use

| Scenario | Behavior |
|----------|----------|
| New project init | Gets the full three-tier system: AGENTS.md core conventions + B-01 real 8 chapters + B-04 feedback template |
| Existing project adoption | Incremental path unchanged: fill gaps only, never overwrite; existing AGENTS.md quality-graded and supplemented by missing sections |

## 5. Diff vs v1.6.1

| Dimension | v1.6.1 | v1.7.0 |
|-----------|--------|--------|
| Base coding conventions | Component-level + 7 general principles only | 6-category base conventions written for real (≤20 core rules + B-01 detailed 8 chapters) |
| AI high-frequency mistakes | Fragmentary coverage | Systematized 7-category 27-entry KB, injected first |
| B-01 conventions doc | One-line placeholder | Real 8 chapters + maintenance |
| Bug feedback | Recorded in B-04 only | Full loop: B-04 → B-01 → AGENTS.md |
| Doc maintenance | No progress reminder | Milestone-based auto-check + "check project progress" command |
| File count | 30 | 32 (+code-conventions.md / +ai-common-mistakes.md) |

## 6. Backward Compatibility

- **No breaking changes**: new KBs + Step enhancements only; Step 1~7 numbering and order unchanged
- Existing projects re-triggering the skill take the incremental path (fill gaps only)
- DSH plugin bundle synced (`dsh-plugin/skills/` matches the repo root)

## 7. Known Limitations & Roadmap

- B-01/B-04 ongoing maintenance relies on in-project agents following the feedback rules; the convention system grows with real practice frequency
- The AI-mistake list is a 27-entry seed version and will keep growing via B-04 feedback
- Future idea: pre-built "stack-specific conventions" templates for more frameworks in B-01

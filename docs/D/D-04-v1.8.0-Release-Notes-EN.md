## 1. This Release in One Sentence

**The skill moves from a "convention generator" to a "convention enforcer / grower" — initialization only seeds generic gates; the project's AI grows domain gates out of real mistakes under constitution-layer meta-rules.**

v1.7.x answered "can conventions be written?"; v1.8.0 answers "**can conventions be enforced and kept alive?**"

## 2. Why This Update

Before v1.8.0 the skill was strong on the **convention layer** (Step 2 assembly + `code-conventions.md` + `ai-common-mistakes.md`) but left the **process layer and verification layer essentially empty**:

| Gap | Impact |
|-----|--------|
| Generated conventions were all "agreements written in docs", with no machine-executable check | Red lines relied on self-discipline; violations went unblocked and conventions degraded into reference docs |
| At init time a project has no code and no real defects, so only generic rules can be produced | Domain red lines (field enum consistency, unit consistency) had nowhere to grow |
| No "defect → gate" sedimentation mechanism | The same pit was hit repeatedly — the convention system "was born but never grew" |

**Evidence from the source project** (see [D-03 report](D-03-真实项目文档体系优化引入评估报告.md) §9): one real project produced **11 check scripts / 21 gate mappings**, ground out of **89 real defect patterns** (roughly a **1/4 consolidation rate**). The scripts `check-agent-enum`, `check-weight-unit`, and `check-numeric-dto` **all appeared only after the mistakes were made**.

**Conclusion**: gates are **defect-driven growth artifacts, not initialization outputs**. Hence the **constitution layer** — meta-rules in `AGENTS.md` that make the AI grow domain gates during development.

## 3. Core Updates

### 3.1 Constitution-Layer Meta-Rules (written into generated AGENTS.md)

Three meta-rules (the whole chapter stays **≤ 15 lines**; details are always linked out, to keep the constitution from bloating):

1. **No gate, no rule** — adding a blocking red line requires submitting an executable check in the same change and registering it in `scripts/gates.json`; if truly not machine-checkable, mark `[无门禁]` and state why
2. **Every defect closes the loop** — after fixing a defect, decide whether it is machine-checkable: if yes → create/extend a gate; if no → file it as a BUG knowledge-base pattern. Changing code without sedimenting is forbidden
3. **Single source of contract** — cross-boundary fields use the DTO/schema export as the single source of truth, and export changes must ship with the code

Plus a **session prerequisite**: the AI reads `scripts/gates.json` at the start of a new session to learn the repo's existing gates and avoid repeating old mistakes.

### 3.2 Gate Growth Flow (6 Steps)

```
① Trigger   defect fixed / AI corrected repeatedly / new blocking red line
   ↓
② Decide    four admission questions (all must pass): machine-checkable? zero new deps? actually happened? false positives controllable?
   ↓ checkable → build gate     ↓ not checkable → write rule only + mark [无门禁] + file BUG pattern
③ Generate  three-tier recipe lookup: cross-language gate recipe table → component Gate section → web search
   ↓
④ Register  ① write the check (scripts/checks/<id>.*)  ② append one entry to gates.json
   ↓
⑤ Verify    negative verification: deliberately violate once and confirm the gate blocks (if it doesn't, it must not be registered as blocking)
   ↓
⑥ Record    BUG knowledge base + protocol doc + CHANGELOG
```

Rationale for the four questions: **machine-checkable** (subjective red lines only produce false green), **zero new deps** (if users must install something, they will bypass the gate), **actually happened** (imagined defenses pile up dead gates), **false positives controllable** (noisy gates get bypassed with `--no-verify` — better downgraded to `warn`).

> Realistic expectation: in real engineering roughly **1/4** of defect patterns end up as gates. **Not every pit deserves one.**

### 3.3 Single Source of Gate List + Unified Entry + Constitution Self-Check

| Artifact | Purpose |
|----------|---------|
| `scripts/gates.json` | Single source of truth for the gate list; fields `id / source / level / stage / run / cwd / why` |
| `scripts/verify.*` | Unified entry; iterates the list, supports `--stage=pre-commit\|pre-push\|ci`, exits non-zero when a `blocking` gate fails |
| `scripts/check-constitution.*` | Constitution self-check; **two-way comparison** between `AGENTS.md` red lines and the gate list — red line with no gate = error, zombie gate = warning |

**Key benefit**: adding a gate = "write the check + append one list entry"; pre-commit / pre-push / CI all take effect through the same entry. **No more "the script exists but was never wired up."**

### 3.4 Gate Recipe Knowledge (Knowledge Base Upgrade)

- `references/knowledge-base.md` gains a **cross-language gate recipe table (10 entries)** in the general section: contract drift / hardcoded secrets / lockfile consistency / debug residue / static checks / formatting / test coverage / migration-vs-model consistency / doc drift / oversized files — each with "generic red line / how to check / cross-language equivalents"
- Component entry format upgraded from **3 sections to 4** (`Commands` / `Conventions` / `CI job` / **`Gate`**); the first batch of **12 high-frequency components** now has `Gate` sections (machine-checkable red line → how to check)
- Benefit: Go / Python / Java / Rust projects get `go vet` / `mypy` / `gradlew check` / `cargo clippy` equivalents instead of a Node script that cannot run

### 3.5 New Step 5.5 "Gate Assembly"

Rules live in `AGENTS.md`, the list is generated in Step 3.5, and **Step 5.5 wires them into commit/CI trigger points and smoke-tests them**:

- **Host fallback order**: existing project entry (`npm run` / `make` / `tox` / `./gradlew` / `just`) → Node → Python → `Makefile` → shell (dual copy)
- **Assembly points**: JS/TS uses husky (pre-commit runs fast checks only, pre-push runs the full set) / Python uses the `pre-commit` framework / Go·Java·Rust use Makefile + CI as the main entry; **CI must reuse the same `verify.*` entry in all languages** (same semantics locally and in CI)
- **Five hard requirements**: zero new deps / must smoke-test after generation / new `blocking` gates require negative verification / `blocking` vs `warn` levels (existing projects default to all `warn`) / exemptions must be registered with a reason and a convergence target
- **Output**: host / assembly points / smoke-test result / blocking vs warn counts, with the smoke-test output kept as evidence

### 3.6 Document Contract + `docs-check` Script (First Gate Seed)

- **Document contract**: B/C-series documents carry a status header `> 版本: … | 更新: … | 状态: …`; unique numbering (a missing number requires an archive or index note); the index covers all non-archived docs; oversized documents must be split
- **`references/docs-check.mjs`**: checks numbering continuity / status headers / index coverage / archive conflicts + single-file size, with **error (blocking) / warning (non-blocking) / info** levels; exit code 0 = no errors
- Legacy debt never blocks: unmet requirements in existing projects' historical docs are warnings — new docs must comply, old ones are backfilled gradually

### 3.7 AI Work Protocol

- **7-step task lifecycle** (no skipping): read conventions → check precedents → define contract → plan → implement → run gates → write back docs
- **Evidence standard**: code changes cite `file:line`; verification cites "command + actual output"; when verification is impossible, explicitly mark "unverified + reason + risk". Statements like "should be fine / looks right / theoretically works" are **forbidden** as substitutes for evidence
- **8-point Definition of Done** + **violation handling table** (declaring completion without running gates → treated as incomplete, sent back to step 6) + **defect retrospective template**
- Artifact: `docs/B/B-06-门禁与工作协议.md` (on demand)

### 3.8 Scale-Threshold Triggering (Avoid Over-Engineering)

Small projects (few source files / single developer) only get **"one gate (docs-check) + the unified entry"** — no `scripts/checks/` directory and no protocol document; medium/large projects get the full gate layer.

## 4. How to Use

| Scenario | Behavior |
|----------|----------|
| New project init | Gets constitution meta-rules + gate list with unified entry + document contract and check script; initialization seeds generic gates, domain gates grow during development |
| Existing project adoption | Incremental path unchanged: fill gaps only, never overwrite; all gates default to `warn` and are upgraded to `blocking` once stable |
| Daily development | AI follows the 7-step protocol; gates run through the same entry in pre-commit / pre-push / CI; after a defect fix, the 6-step growth flow decides whether a gate is added |

## 6. Backward Compatibility

**BREAKING (flow-structure change, not data damage)**

- `SKILL.md` adds **Step 5.5 "Gate Assembly"**; Steps 2 / 3 / 4 / 5 / 6.5 / 7 all adjusted; the acceptance checklist changes (more artifacts)
- Re-running initialization on an existing project adds sections and files to `AGENTS.md` and `docs/` (**incremental, never overwriting existing content**)
- New artifacts: `scripts/gates.json` / `scripts/verify.*` / `scripts/check-constitution.*` / `scripts/docs-check.*` / `docs/B/B-06-门禁与工作协议.md` (on demand) / `docs/issues/`
- Existing projects default to all gates at `warn` level, so commits are not suddenly blocked
- DSH plugin bundle synced (`dsh-plugin/skills/` matches the root `SKILL.md` + `references/`, 12 reference files)

## 7. Known Limitations & Roadmap

- Component `Gate` sections are **not filled in at once** (12 of 70+ components in the first batch) — most components have no real-mistake evidence yet, and speculative gates only produce dead gates; the rest are added batch by batch as components are encountered
- A full language-specific `check-*.mjs` domain script library is **not shipped** — domain checks are tightly coupled and are grown by the consuming project via the growth flow
- How fast gates grow depends on real project activity and whether the AI follows the meta-rules
- Possible next step: port `docs-check.mjs` to Python / shell equivalents to cover more hosts

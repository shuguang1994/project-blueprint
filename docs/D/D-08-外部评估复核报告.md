> 版本: v1.0 | 更新: 2026-09-18 | 状态: 已完成
> 复核对象：一份外部 AI 助手（DeepSeek）对 Project Blueprint 的「项目价值全面评估」（3 轮对话，含用户补充的 v1.9.0 更新速览 HTML）

***

## 一、复核方法与判定口径

| 证据类型 | 具体手段 |
|---------|---------|
| 仓库实测 | 逐文件计数（行数 / 字节 / `###` 条目 / `##` 章节 / `**Gate**` 段），node 与 PowerShell 双法交叉 |
| 门禁实跑 | `scripts/verify.mjs` / `references/docs-check.mjs` / `references/drift-check.mjs` / `scripts/check-constitution.mjs` |
| 外部独立核查 | GitHub REST API、arXiv abstract 页、第三方站点与博客抓取 |
| 交叉对照 | CHANGELOG 各版本自述、`docs/D/` 历史报告、`scripts/gates.json` 的 `why` 字段 |

**判定口径**：凡「可机检或可外部核实」的断言逐条判定（✅ 通过 / ❌ 失实 / ⚠️ 无法核实）；主观评分不判定，仅标注其证据基础。

***

## 二、复核结论

**项目自身的硬事实基本全部可复现；但该外部评估在时效性、数据准确性与引用来源上存在硬伤，不能作为独立第三方评估引用。** 复核过程另发现仓库侧 5 项待闭环问题（本轮已处置 4 项）。

## 四、评估侧失实与问题（6 项，按严重度）

### 4.1 引用污染：把无关内容当作本项目来源（最严重）

| 外部评估引用的「来源」 | 实际情况 |
|---------------------|---------|
| `docs-blueprint.vercel.app/blog/tags/performance` | 抓取失败，非本项目站点，仓库无 Vercel 文档站 |
| `raw.githubusercontent.com/LiarMTTT/TavernWeave/main/CHANGELOG.md` | 另一个无关项目（TavernWeave）的 CHANGELOG，被当作本项目 changelog 的佐证 |
| gitcode「web-to-app 的 AGENTS.md 深度解读」 | 与本项目无关的第三方文章 |
| dev.to「The Blueprint for AGENTS.md and System Prompts」 | 通用 AGENTS.md 文章，与本项目无关 |

**影响**：把搜索结果中语义相近但对象不同的页面混成本项目来源，使结论看起来有旁证，实际不成立。

### 4.2 数据全面过期且未标注时效

| 指标 | 外部评估 | 实测（2026-09-18） | 过期来源 |
|------|---------|------------------|---------|
| GitHub star | 13（后又称「13-19 区间」） | **21**（1 fork） | 第三方博客（v1.7.1 期）与作者 v1.0 期论坛帖 |
| 语言数 | 8 种 | **7 种** | 论坛帖（v1.5.0 已由 8 修正为 7） |
| 组件数 | 70+ | **95 个组件条目** | 同上 |

### 4.3 Star 对比类比无效

称 `MartinHeinz/python-project-blueprint`「已有 956 stars」——实测 **974**；且该仓库是 Python 项目模板（boilerplate），与本项目（Agent 技能包）不同类目，不具备可比性。

### 4.4 把营销数字当既成事实

评估开篇断言「Anthropic 内部基准测试显示，有 AGENTS.md 的项目可减少 40-60% 的错误模式重写」，实为 README / 作者论坛帖的自述，**仓库未提供任何引用来源**。同一批数据中，独立第三方博客反而明确标注「非本文独立核实」，外部评估省去了该标注。

更值得注意：该 40-60% 的乐观表述与项目自己在 D-07 引用的 ETH SRI 论文结论（context file **不普遍提升**任务成功率）存在张力，属需进一步说明的对外表述风险（见 §八遗留项）。

### 4.5 「Gitee 无法访问」为评估工具自身限制

外部评估首轮称「Gitee 链接无法直接打开」，随后以二手资料代替一手的仓库核查。实测 `git ls-remote gitee` 正常返回全部 tag，仓库可访问。

### 4.6 末段未收束，评分无方法说明

- 抓取到的分享内容止于「需要理性看待的方面」第二条，未见最终评分与建议收束；
- 中途「综合价值评分 3.5 / 5 → 上调至 4.0」为主观判断，未给出评分方法或权重说明；改分的直接原因是用户在对话中补充了资料，而非评估方独立核实；
- 评估方自认「v1.9 版本公开渠道尚未检索到明确更新说明」——这一点与事实相符（第三方资料多停留在 v1.7.1），但由此得出的项目判断已落后 2 个版本。

## 五、仓库侧待闭环问题与本轮处置

| # | 问题 | 证据 | 本轮处置 |
|---|------|------|---------|
| 1 | **GitHub 落后 Gitee 2 个 commit**（`origin/main` = `8a9a819`，`gitee/main` = `329dcca`），落后的提交含 v1.9.0 中英发布说明与文档索引登记 | `git log origin/main..HEAD` | 本轮补推（见 §六） |
| 2 | **README / SKILL / AGENTS / PROJECT_STATUS / package.json 对外数字口径未统一** —— 组件 6 处 `70+` 与汇总行 `95` 并存；业务类型 6 处 `13 种` 与汇总行 `12 种` 并存（违反 AGENTS.md「对外数字口径唯一源」） | `grep -n "70+\|13 种"` | 已统一为 `95 个组件条目` / `12 种` |
| 3 | **GitHub 仓库 description 严重过期** —— 仍为 `7 languages × 14 frameworks × 61 components`（61 为 v1.2.0 口径） | GitHub REST API | 本轮尝试更新（见 §六） |
| 4 | **文档索引链接指向不存在的文件** —— `docs/README.md` 链接 `./D/D-06-v1.9.0-更新速览.html`，实际文件为 `v1.9.0-更新速览.html` | 目录比对 | 已按索引口径重命名实际文件 |
| 5 | **工作区未提交 / 未跟踪** —— `PROJECT_STATUS.md`、`docs/README.md` 有未提交改动；`D-07` 与更新速览 HTML 未被 git 跟踪（即外部评估末轮引用的两篇论文只存在于未发布草稿） | `git status` | 本轮一并提交 |

### 5.6 门禁盲区（本轮暴露，需后续补门禁）

`references/docs-check.mjs` 第 209 行的索引链接校验正则只匹配 `.md` 链接：

```js
for (const m of indexText.matchAll(/\]\(\.\/([^)]+\.md)\)/g)) { ... }
```

因此索引中指向 `.html` 等非 `.md` 文件的相对链接**不参与校验**，问题 4 的失效链接由此长期漏检（docs-check 报告 `0 error`）。属「门禁即规则」元规则下应补的一条门禁（建议：链接校验扩展到全部相对链接，或至少覆盖 `.html`），本轮仅记录，未改动校验逻辑以免影响既有生成物。

## 七、对「外部评估」可用性的结论

| 维度 | 可用性 |
|------|-------|
| 项目定位与产品判断方向 | 基本可用（「方向正确、执行扎实的垂直工具」站得住） |
| 具体数字与版本事实 | **不可用**（star / 语言数 / 组件数全部过期） |
| 引用来源 | **不可用**（存在 4 处无关来源混入） |
| 评分与改分 | **不可用**（无方法说明，且改分由用户补料驱动） |
| 作为对外引用材料 | **不建议**；如需对外引用，应以本报告 §六 的实跑记录与仓库自身 CHANGELOG「验证」段为准 |

## 八、遗留项与建议

| # | 遗留项 | 建议 |
|---|-------|------|
| 1 | 业务类型 `12 条` 的构成含 1 条兜底（「未知类型」）与 1 条实为生成规则的标题（`### 模块速查表生成规则`） | 将「模块速查表生成规则」提升为独立二级章节更准确；但会使二级章节 18 → 19，牵动 AGENTS.md / README 多口径，属独立变更，本轮未动 |
| 2 | README 开篇「行业数据」（40-60% 错误模式重写 / 76% 开发者 / 60,000+ 仓库）均无引用来源 | 标注来源，或降级为「社区经验值」表述；避免与 D-07 引用的 ETH 结论（context file 不普遍提升成功率）形成自相矛盾 |
| 3 | `docs-check` 索引链接校验仅覆盖 `.md` | 扩展为覆盖全部相对链接（见 §5.6），并登记为门禁 |

| 5 | 历史快照文档（D-01 / D-03 / D-04 / D-05、CHANGELOG 历史条目）保留 `70+`、`13 个二级章节 / 80 个组件条目` 等旧数字 | 按「历史快照不追改」原则保留，不逐一回填 |

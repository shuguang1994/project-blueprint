# v1.7.0 功能发布说明 — 代码规范闭环增强

> 发布: 2026-08-14 | 版本: v1.7.0（minor，无破坏性变更） | 升级方式: `npx skills update project-blueprint` 或 `dsh plugin --profile web add 'github:shuguang1994/project-blueprint'`
> English version: [D-02-v1.7.0-Release-Notes-EN.md](D-02-v1.7.0-Release-Notes-EN.md) | 上一篇: [v1.6.1](https://github.com/shuguang1994/project-blueprint/blob/main/CHANGELOG.md)（DSH 插件 GitHub 安装路径修复）

## 一、本次更新一句话

**初始化项目时，从"只有规范骨架"升级为"实际写入基础代码规范"，并建立 AGENTS → B-01 → B-04 三层反哺闭环，让代码规范随项目实战持续进化、防止 AI 重复犯错。**

## 二、为什么做这次更新

v1.7.0 之前的初始化存在三个真实缺口：

| 缺口 | 影响 |
|------|------|
| 只生成**组件级规范**（如 NestJS/Vue 特定约定），缺少横向基础规范 | 命名、错误处理、日志、安全、性能等通用规范靠模型临场发挥，风格飘忽 |
| `docs/B/B-01-开发规范.md` 只是**一行占位符** | 初始化后没有实际写入任何编码规范 |
| AI 高频错误只有碎片化覆盖，Bug 无法反哺规范 | 同一个错误模型会重复犯，规范体系"只生不长" |

## 三、核心更新

### 3.1 三层代码规范体系（AGENTS → B-01 → B-04）

```
L1  AGENTS.md 强制规范（核心，≤20 条，模型每次编码前必读）
       │ 引用                         ↑ 反哺
L2  docs/B/B-01-开发规范.md（详细 8 章，按需查询）
       │ 引用                         ↑ 反哺
L3  docs/B/B-04-BUG知识库.md（实际 Bug 沉淀，含「规范反哺」字段）
```

- **L1**：命名/错误/日志/安全/性能 5 类核心规则（每类 ≤4 条），AI 高频错误防犯规则优先注入
- **L2**：B-01 从占位符改为**实写 8 章**（命名/目录结构/错误处理/日志/安全/性能/技术栈特定/AI 高频错误防犯清单 + 规范维护）
- **L3**：B-04 模板新增「是否规范缺失 / 规范反哺」字段——修复 Bug 根因是规范缺失时，自动反哺更新 L1/L2

### 3.2 新增知识库一：基础代码规范种子库（code-conventions.md）

6 大类 × 语言适配（TypeScript / Go / Python / Java / 数据库），每类含 ✅/❌ 规则 + 联网搜索模板。作为**确定性基线**（保下限），大模型知识负责展开、联网搜索补充未知技术栈（保上限），遵循三层递进设计。

### 3.3 新增知识库二：AI 高频错误防犯库（ai-common-mistakes.md）

**本次最高优先级专项**。7 大类 27 条，每条六段式（AI 易错点 / 后果 / ❌ 错误示范 / ✅ 正确做法 / 关联知识库 / 搜索模板）：

```
依赖/API · 数据/性能 · 错误处理 · 安全 · 类型/语言 · 工程规范 · Git
例：凭旧记忆写 TypeORM 0.2 API → 0.3 不兼容 → ❌示范 + ✅ AppDataSource 写法
```

Step 2 生成 AGENTS.md 时**按探测技术栈优先注入**对应防犯规则，未覆盖的易错点触发联网搜索。

### 3.4 BUG → 规范反哺闭环（Step 7 增强）

修复 Bug 且根因是 **AI 犯错**时：

1. 检查是否命中 ai-common-mistakes 清单
2. **命中** → 强化对应规则（B-01 标注出现次数）
3. **未命中** → 新增清单条目 + B-01 补规则 + AGENTS.md 加一条 ✅/❌ 防复发

一次修复 = 一次规范进化，从源头防止模型重复犯错。

### 3.5 项目进度与文档健康检查

生成的 AGENTS.md 注入「项目进度与文档健康检查」机制，Agent 在以下里程碑主动检查文档滞后并提醒用户维护：

| 里程碑 | 检查项 |
|--------|--------|
| 新功能完成 | 模块速查表 / 技术栈行 / 代码规范是否需补充 |
| 重构完成 | 架构决策表 / 目录结构 / 耦合度分析 |
| 上线前 | B-02 部署指南 / CI 描述 / 检查清单 |
| 季度末 | 项目记忆清理 / B-04 归档 / 规范体系回顾 |

用户说"看下项目进度" → Agent 输出：最近进展 + 文档滞后清单 + 建议维护项。

### 3.6 配套文档同步（全体系联动）

| 文件 | 更新 |
|------|------|
| `references/knowledge-base.md` | 通用段落 +4 条 AI 防犯原则（不吞错误 / 不只走 happy path / 不硬编码密钥 / 先读现有代码）；代码审查清单 +5 条 AI 高频检查项 |
| `references/docs-skeleton.md` | B-01 描述更新为实写 8 章（权威源/反哺源声明），B-04 描述加入「规范反哺」字段 |
| `references/agents-md-template.md` | 兜底模板新增 4.5 节（代码规范体系 + AI 高频错误防犯规则） |
| `README.md` / `README_CN.md` | 核心能力表 +2 行、生成内容补 B-01 实写说明、与众不同之处 +1 行、贡献指南 +2 行 |

## 四、使用方式

| 场景 | 行为 |
|------|------|
| 新项目初始化 | 直接获得完整三层规范体系：AGENTS.md 核心规范 + B-01 实写 8 章 + B-04 反哺模板 |
| 已有项目接入 | 增量路径不变：只补缺失，不覆盖已有配置；对已有 AGENTS.md 按质量分级补充缺失章节 |

## 五、与 v1.6.1 差异速览

| 维度 | v1.6.1 | v1.7.0 |
|------|--------|--------|
| 基础代码规范 | 仅组件级 + 通用原则 7 条 | 6 大类基础规范实写（≤20 条核心 + B-01 详细 8 章） |
| AI 高频错误 | 碎片化覆盖 | 7 大类 27 条系统化知识库，优先注入 |
| B-01 开发规范 | 一行占位符 | 实写 8 章 + 规范维护 |
| Bug 反哺 | 只记录到 B-04 | 反哺闭环：B-04 → B-01 → AGENTS.md 三级联动 |
| 文档维护 | 无进度提醒 | 按里程碑自动检查 + "看下项目进度"指令 |
| 文件数量 | 30 | 32（+code-conventions.md / +ai-common-mistakes.md） |

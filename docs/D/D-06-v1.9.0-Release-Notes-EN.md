## 1. This Release in One Sentence

**v1.8.0 made conventions enforceable; v1.9.0 makes them portable across stacks and drift-resistant — the skill body is slimmed into a lazily-loaded index layer, multi-package repositories get nested AGENTS.md files per the official closest-file-wins rule, and a second seed gate turns "code/deps ↔ conventions" mismatches into machine-checkable events.**

v1.8.0 answered "**can conventions be enforced and kept alive?**"; v1.9.0 answers "**do they scale to any stack — and do they stay accurate?**"

## 2. Why This Update

[D-05](D-05-行业对标与体系完备性评估报告.md) evaluated v1.8.0 both locally (byte-level, command-level evidence) and against the wider ecosystem (2026 public sources). Verdict: **completeness 9/10, universality 7/10, systematic leadership 7.5/10**, with 10 verifiable gaps concentrated in three areas:

| Gap | Impact |
|-----|--------|
| `SKILL.md` body at **1,012 lines / 50,203 bytes** | **2× over** Anthropic's official "SKILL.md body < 500 lines" guidance; only 2 layers of progressive disclosure, so the whole body loads at once and eats the context budget |
| Monorepo missing the official semantics | AGENTS.md's documented rule is **closest-file-wins**; this skill previously "wrote all sub-project conventions into the root file as blocks" — large repos bloat the root file and lose locality |
| No "code/deps ↔ conventions" drift gate | Only doc-internal consistency (`docs-check`) and red-line ↔ gate consistency (`check-constitution`); yet **drift is the ecosystem's #1 acknowledged gap** (a 10,008-repo study: 58% of agent config files have a single-commit history, revision rate just 0.4 commits/month) |

Seven further universality and consistency gaps (KB skewed to web full-stack, spec-driven development not turned into a workflow, breadcrumbs only, this repo's own gates idling, conflicting published numbers, no quality baseline) were closed in the same release.

## 3. What's New

### 3.1 `SKILL.md` split into an index layer (progressive disclosure)

| Item | Before | After |
|------|--------|-------|
| `SKILL.md` | **1,012 lines / 50,203 bytes** (one file carrying all 7 steps) | **113-line index layer** (triggers / execution principles / **step index & lazy-load table** / acceptance checklist / reference index) |
| Step details | all inline | `references/step-1-discovery.md` … `step-7-adaptive.md` (7 files, **61–293 lines each**, all ≤ 500), **read one step at a time** |
| Step 5.5 | separate section | merged into `step-5-ci-and-gates.md` (semantics unchanged) |

**Zero content loss**: verified against the pre-split backup (1,013 lines) — of the original **78 `##`/`###` headings, 76 matched exactly and 2 were renamed (content preserved) → 0 lost**; 31 extra semantic anchors all matched; **0 duplicated long lines** across files (no second source of truth).

### 3.2 Nested AGENTS.md for monorepos (official closest-file-wins)

- **Trigger**: **≥ 2** build/manifest files found in subdirectories (`package.json` / `go.mod` / `pyproject.toml` / `pom.xml` / `Cargo.toml` / `composer.json` / `*.csproj`, …)
- **Output**: root `AGENTS.md` (**global constraints + sub-project index table**) plus a package-level `AGENTS.md` in each sub-project (package stack / commands / package conventions + `Gate` commitment / package module table / one-line pointer to the root file)
- **Single source of truth**: a constraint lives in exactly one place — package conventions never go into the root file, root conventions are never duplicated per package
- **Zero change for single projects**: with only one manifest file, behavior is identical to v1.8.0 (root file only)
- **Incremental-friendly**: an existing package `AGENTS.md` is only supplemented, never overwritten; the gate registry `scripts/gates.json` stays at the repo root and package gates point at subdirectories via `cwd`
- New reference: `references/monorepo-agents.md`

### 3.3 Convention drift gate (second seed gate)

A zero-dependency reference implementation, `references/drift-check.mjs`, turns "code/deps ↔ conventions" mismatches into machine-checkable events via three checks:

| Check | What it does | Verdict |
|-------|--------------|---------|
| A — deps ↔ conventions | Parses `package.json` / `go.mod` / `requirements*.txt` / `pyproject.toml` and checks whether each dependency is mentioned in `AGENTS.md`'s tech-stack lines | not mentioned → `warning` (configurable ignore list filters build-tool noise) |
| B — module table ↔ real directories | Compares first-level source directories against the AGENTS.md module table | differences either way → `warning` |
| C — gate validity | Verifies that every script referenced by `gates.json`'s `run` exists | missing → `error` (zombie gate) |

**Seed gates went from 1 to 2**: `docs-consistency` + `spec-drift`, keeping the "`blocking` for new projects / `warn` for existing ones" rule. The cross-language gate recipe table gained 3 drift recipes (dependency manifest / module table / spec ↔ code, with an explicit split of duties against the existing "contract drift" row).

### 3.4 Knowledge base extended to 5 new domains (15 components)

`references/knowledge-base.md` gained 5 dimension sections and **15 component entries**, each with all four parts (`Commands` / `Conventions` / `CI job` / `Gate`):

| New domain | Entries | Components |
|------------|:---:|------------|
| AI/LLM stack | 4 | LangChain / LangGraph, LlamaIndex, pgvector, Ollama / vLLM |
| IaC & cloud native | 3 | Terraform, Helm, Kubernetes manifests (kubectl / kustomize) |
| Observability | 3 | OpenTelemetry, Sentry, Prometheus + Grafana |
| Data engineering | 2 | dbt, Airflow |
| Native mobile | 3 | Flutter, SwiftUI (Swift), Jetpack Compose (Kotlin) |

Detection rules were extended too: the file-pattern table gained **8 rows** and the name-pattern table **6 rows** (covering `terraform` / `helm` / `dbt` / `opentelemetry` / `pubspec.yaml` / `build.gradle.kts`, …). Knowledge base now: **917 lines / 18 sections (16 stack dimensions) / 95 component entries**, with commands and versions verified against current official docs.

### 3.5 Spec-driven development, six phases

New `references/spec-driven.md`: **specify → plan → tasks → checklist → implement → verify**, each phase with **artifacts + entry criteria** (you may not advance until the gate is passed); includes the three-file templates and a "checklist → gate" rule (`source: spec#<change-id>`, reusing the existing 7-field `gates.json` schema with no new fields). Section 3.3 of `step-3-docs.md` was upgraded from "documenting the three files" to an actual workflow; `docs-skeleton.md` and `project-sync-guide.md` were synced (the latter gained a "convention drift repair" scenario).

### 3.6 Per-tool private enhancement layers

New `references/vendor-breadcrumbs.md`: beyond the original **5 baseline breadcrumbs** (`CLAUDE.md` / `.cursor/rules/project.mdc` / `.github/copilot-instructions.md` / `.gemini/GEMINI.md` / `.windsurfrules`), the skill now emits each detected tool's **private enhancement layer**:

- **Cursor**: an `alwaysApply` entry plus directory-scoped glob rules (only the non-obvious constraints for that directory)
- **Claude Code**: `CLAUDE.md` pointer + a `.claude/settings.json` hooks skeleton calling `scripts/verify.*` + `.claude/agents/` subagent skeletons
- **Copilot**: `.github/copilot-instructions.md` + `.github/instructions/*.instructions.md` (with `applyTo`)
- Built-in **anti-drift clause**: enhancement layers must not copy convention prose (that would create a second source of truth); on conflict, `AGENTS.md` wins; existing config files are only appended to, never overwritten

### 3.7 Dogfooding: this repo's own gate layer (`scripts/`)

The skill had always generated gate layers for **other** projects while this repo had none — running `docs-check` here skipped **all 5 checks** because `docs/B` and `docs/C` don't exist (`0 error` was a false green). Fixed:

| Action | Result |
|--------|--------|
| `docs-check.mjs` scope made adaptive | Iterates over the `docs/` subdirectories that **actually exist** (missing directories no longer skip whole blocks), plus a new duplicate-number `error` rule; backward compatible (behavior with `docs/B` / `docs/C` present verified unchanged in a sandbox diff) |
| New repo gate layer | `scripts/gates.json` (2 gates) + `scripts/verify.mjs` (unified entry, supports `--stage=`) + `scripts/check-constitution.mjs` (rules A–D) |
| Negative verification | Duplicate-number doc → `1 error`, exit 1; header-less doc → warning, non-blocking; both fully reverted afterwards |
| New docs index | `docs/README.md` (A–E classification conventions + maintenance rules + D-series registry), dropping legacy warnings **5 → 1 → 0** |

> Design note: the skill-side check scripts (`docs-check.mjs` / `drift-check.mjs`) stay in `references/` as **reference implementations** and are not copied into `scripts/` (avoids two sources of truth).

### 3.8 Quantified evaluation baseline

New `references/eval-baseline.md`: **size metrics** (`SKILL.md` ≤ 200 lines / step files ≤ 500 / `AGENTS.md` ≤ 300 / single doc ≤ 600 / single KB file ≤ 950 / balanced code fences as an error) + **closed-loop metrics** (defect→gate conversion rate, gate coverage — each with data source, formula and false-positive risk) + **3 golden cases** (TS monorepo / Go backend / Python data pipeline) that define expected artifacts and check points without creating sample repos.

### 3.9 Single source of truth for published numbers

Five drift cases fixed against the knowledge base as the authority: the reference index now covers **24/24** files; the stack-dimension list went 11 → **16** (with web-search fallback templates for the 5 new dimensions); component headings unified to `### [Component]`; the KB header no longer over-claims ("every component has 4 parts" → 27 of 95 entries carry a `Gate` part); MCP figures unified as "§1 mapping table 14 rows + §2 18 tool entries".

## 4. How to Use It

| Scenario | Behavior |
|----------|----------|
| New project | Single project → root `AGENTS.md` only (same as v1.8.0); multi-package → root + per-package `AGENTS.md`; **2 seed gates** registered |
| Existing project | Incremental path unchanged: fill gaps, never overwrite; existing package `AGENTS.md` files are supplemented section by section |
| Day-to-day | Gates run through `scripts/verify.*` at pre-push / CI; after dependency or directory changes `spec-drift` reports the divergence and you repair per the "convention drift repair" scenario in `references/project-sync-guide.md` |
| Large changes | Follow the six phases in `references/spec-driven.md`; machine-checkable checklist items can be registered as gates directly |

## 6. Backward Compatibility

**BREAKING (workflow structure, not data)**

- **`SKILL.md` restructured**: the body is split into a 113-line index plus 7 `references/step-*.md` files (`references/` went from 12 to 24 files). If external docs or scripts locate `SKILL.md` by section, point them at the matching step file (heading text is preserved to ease migration)
- **Multi-package output structure changed**: the root `AGENTS.md` becomes "global constraints + sub-project index", with package conventions moving into each sub-project's own `AGENTS.md`
- Both changes are **additive — nothing existing is overwritten**; **single-project behavior is identical to v1.8.0 (zero change)**
- The new `spec-drift` gate defaults to `warn` for existing projects, so commits are not blocked abruptly
- The DSH plugin bundle is in sync (`dsh-plugin/skills/` matches the root `SKILL.md` + `references/`, 24 files each, identical SHA256)

## 7. Known Limitations & Next Steps

- **`drift-check.mjs` check A covers Node manifests only** (`package.json`) — non-Node projects get an `info` skip; `go.mod` / `requirements*.txt` / `pyproject.toml` are supported, Java (`pom.xml`) and Rust (`Cargo.toml`) are not yet
- **The monorepo nested mode has not been run end-to-end on a real multi-package repo** (rules and cross-references are in place and verified by tracing)
- React UI libraries (MUI / shadcn/ui) are still absent from the KB (web-search fallback applies); Fastify / Actix-web entries are still missing
- The KB at **917 lines** is close to the 950-line ceiling; further growth needs splitting by dimension (see the size metrics in `eval-baseline.md`)
- Nests deeper than 3 levels may still need a manual re-trigger; a Gitee project that already has GitHub Actions won't be offered `.gitee-ci.yml`
- Possible next steps: port `drift-check.mjs` to Python / shell for more hosts; add non-Node manifest parsing

## 1. In One Sentence

**We fixed the root cause of "CI looks green but checked nothing."**

If you have initialized a project with Project Blueprint, this release is worth upgrading — it fixes problems in **the generated artifacts themselves**, not just the wording. The three most common kinds of "fake green":

| What you see | What is really happening | v2.0.0 |
|--------------|--------------------------|--------|
| CI is all green ✅ | The test step carries a "zero tests still passes" switch → **green even with no tests written** | The switch is gone. **Zero tests = red** (which is what test runners do by default) |
| CI has a "gates" step | The gate job is a fragment you must **paste by hand** → never pasted, never ran | The gate job is **inlined** into the generated workflow; "forgot to paste" no longer exists |
| Gates show ✅ | With no source directory / dependency manifest, checks **skip silently** and print one info line | Now an explicit "**not applicable + reason + risk**"; where a fallback comparison is possible, it **actually compares** |

v1.9.0 made conventions *portable and drift-resistant*; v2.0.0 makes the convention system *incapable of faking green*.

## 2. Why This Release

These are not hypothetical. All three showed up in real projects, and all three trace back to **the same generation template**:

| Symptom | Real record |
|---------|-------------|
| Green with zero tests | A project's CI copied the template's test step verbatim; its own self-review reads: "because specs were never committed, **CI effectively runs empty (fake green)**" |
| Gates never executed | In one Gitee Go environment the plugin provided no `node`/`npm`, so all 5 commands in the stage died instantly with `command not found` (the pipeline *looked* "running"); its docs read: "**CI has never actually executed a single gate since it was created**" |
| 40 gates, only 5 reached CI | Gates were offered as "append this fragment", and manual wiring missed most of them |
| Renaming a spec file silently disabled checks | Gates referenced convention entries by **section name**; after a rename nobody noticed |
| "Constitutional review" only checked one direction | It could detect "the convention a gate points at is gone" but **not "a convention was written and nobody enforces it"** |

## 3. What Was Fixed (Item by Item)

### 3.1 Fake-green switch: zero tests no longer pass

- **14 places** in the generated CI template and component knowledge base carried a "zero tests still passes" switch — **all removed**
- The reason is simple: those switches do exactly one thing — disguise "not tested" as "tested"

| Test runner | Default behavior with zero tests |
|-------------|----------------------------------|
| vitest / jest / mocha | Reports `No test files found`, **exits non-zero** |
| pytest | **Exit code 5** (non-zero) |
| Go `go test` | Exits 0 with no test packages (Go's built-in semantics — different from a fake-green switch) |

**"Zero tests means red" is already the default**, so the fix is to **delete the switch**, not swap it for another one.

**How the test step is handled**: in the generated workflow the test step carries an explicit marker; pick one of two actions based on Step 1's detection:

| Detection result | Action |
|------------------|--------|
| A test framework or test files were detected | **Keep** the step |
| Nothing detected | **Remove** the step and record the "add a CI test step once tests exist" contract in `docs/B/B-03-测试指南.md` |
| Go projects | `go test ./...` is **kept unconditionally** |

### 3.2 Gate wiring: no longer relies on "remember to paste"

- All four language workflows (TypeScript/NestJS, Vue/React, Go, Python) **now contain** the gate job, calling `scripts/verify.*` directly
- **The "append this fragment" step is gone** — the failure mode "forgot to wire it" no longer exists
- If your project **already has** a CI file, the skill skips and does not overwrite it; but the generation report **verifies that it really calls the gate entry**, and explicitly flags "gate not wired + risk" rather than staying silent

**A hidden trap fixed along the way**: the old template had CI call `make verify` (Go) and `python scripts/verify.py` (Python), but **neither host was ever generated** — referencing something that does not exist means that step necessarily fails. This release ships **runnable** Python gate entry and constitution self-check implementations, plus a hard rule: **whichever host CI references, that host must actually be generated.** The two hosts were measured to be semantically identical (same gate manifest → same gates → same exit code).

### 3.3 Convention references: stable IDs, so a rename no longer breaks the link

**The old risk**: gates referenced conventions by section name (`AGENTS#文档契约`). Rename or restructure that section and **nothing notices**.

**The new form**:

```
source: "AGENTS#RL-01@文档契约"
        └ stable ID (authoritative) ┘ └ human-readable hint; renames don't matter
```

- **Stable IDs**: `RL-01`, `RL-02`, … **append-only, never reused**; to retire one, set its tier to `retired` rather than deleting the row
- **New red-line authority table** `docs/B/B-00-红线与门禁映射.md`: each row is `ID | tier | red line | owning gate | check | no-gate reason`
- **Why `docs/` and not `AGENTS.md`**: AGENTS.md is an index layer (≤ 300 lines). Putting the list there creates "one copy in each place", which inevitably drifts on renames. **AGENTS.md only indexes; the list has exactly one home.**
- **The authority table is generated together with the gate manifest**: generating only the manifest degrades the two-way check, leaving it "half installed"

### 3.4 BUG knowledge base: one heading format, so the metric is computable

**The problem**: the same thing was written 4 different ways along the generation path, while the "defect → gate conversion rate" metric counts only one of them. Measured on two real projects, that rule counts **0** for both (they really have 142 and 60 entries) — **the metric was uncomputable, i.e. effectively absent**.

**The fix**: one format — `## BUG-<NNN> | <title>` (zero-padded, unique, never reused) + a symptom lookup table at the top + a six-part entry body. The documentation skeleton states this is the **only** format, and the other four places (generation template / entry internals / sync guide / counting rule) all reference it.

### 3.5 Idle gates: say "not applicable", and compare when you can

**Old behavior**: on projects with no source directory or dependency manifest, checks **skipped outright** and printed a single line, "skipping check A" — looked green, checked nothing.

**New behavior** (both were done):

| Action | Effect |
|--------|--------|
| **Required**: print an applicability ruling | One format — `不适用｜原因：…｜风险：…｜裁定` — which cleanly separates "not checked" from "checked and fine" (exit code unchanged, so it never raises a false red) |
| **Fallback comparison** | With no source directory, compare **repository top-level dirs ↔ module table** instead. **Docs-only / frontend-only projects therefore get genuinely checked for the first time** (measured: it reports "the table lists `src`, but that path does not exist") |

The fallback mode ships an editable noise exclusion list; "the table lists a path that does not exist" is a `warning` (zero false positives), while "a directory exists but is not in the table" is only `info` (top-level dirs are often tools/docs rather than "modules", so warning would spam).

**One new companion check**: a test framework / test files detected but no test step in CI → `warning` ("tests were built but never wired into CI"). This prevents "just delete the test step" from becoming the next silent defect.

### 3.6 Constitutional review: both directions now work

**Two problems with the old implementation**:

1. **One direction only** — it caught "the convention a gate points at is gone" but **not "a convention was written and nobody enforces it"** (the more dangerous direction)
2. **The generation side used an outdated template** — its rule depended on a special annotation in the conventions file that the generation side **never produces** ⇒ the rule **never fired**. Measured across three drill projects it printed "0 error / 0 warning / 0 info": **it ran and checked nothing**

**The new implementation**:

| Item | Content |
|------|---------|
| Two-way check | ① every convention a gate references must exist (anti-zombie); ② **every convention at `blocking` tier must be enforced by at least one gate** (anti "rule with no gate") |
| Legacy format tolerated | Section-name references still parse, but prompt migration (`warning`) instead of erroring |
| **Degrade, never silently** | With no authority table: fall back to section-name matching, and **two notices are mandatory** — ① that it degraded; ② **the uncovered risk** ("cannot detect a blocking convention that has no gate"). **Going quietly green is not allowed.** |
| No day-one red for an unbuilt table | Without the table, a failed lookup is a `warning`; once the table exists it returns to `error` |

### 3.7 Runtime self-verification: environment problems surface on line one

Every CI job's **first command** now verifies its own runtime (`command -v` check + version print, installing if missing):

```yaml
- name: 运行时自证
  run: |
    command -v node >/dev/null 2>&1 && command -v npm >/dev/null 2>&1 \
      || (echo "[runtime] node/npm missing, installing" && (apt-get update -y && apt-get install -y nodejs npm \
          || (curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y nodejs)))
    node -v && npm -v
```

One line of cost; the payoff is that **"runtime missing" appears on line one** instead of scattering into several `command not found` lines that get misread as "gate failures". On hosted runners it is a no-op; on self-hosted machines and Gitee Go it is a lifesaver (see the real record in §2).

### 3.8 Similar traps fixed in the same pass

Real-project audit findings were used as a checklist to re-audit the generation path; four more were fixed:

| Trap | Impact |
|------|--------|
| A quality-evaluation doc referenced a **check item number that no longer exists** | Docs and implementation out of sync; readers misled |
| The old template referenced `make verify` / `verify.py` with no implementation | See §3.2 (phantom host) |
| Seed gates gave convention anchors **from a different source** than the AGENTS.md template headings | A new project's first check run either errors or silently does nothing |
| BUG base internal numbering and file-name numbering were **not the same numbering space** | See §3.4 (numbering semantics drift) |

## 4. Upgrade Guide (**includes Breaking Changes**)

> This is a **major** release: **the structure and verification semantics of generated artifacts changed.** Projects initialized earlier should migrate the 3 items below. **Nothing fails silently** — the check scripts report these explicitly instead of pretending to pass.

| # | Change | What you do | If you don't |
|---|--------|-------------|--------------|
| 1 | Gate `source` goes from `AGENTS#<section>` to `AGENTS#<ID>[@<section>]` | Give each `source` a stable ID and register the same ID in the authority table | The check warns "section-name reference used" (`warning`), and a rename still breaks the link silently |
| 2 | **New mandatory artifact** `docs/B/B-00-红线与门禁映射.md` | Create the table and register existing convention red lines as `RL-NN` | The two-way check degrades to one-way (zombie gates only), and it states the degradation and the risk |
| 3 | BUG base headings unified to `## BUG-<NNN> \| <title>` | Rewrite `### 模式 XX：` / `§2.NN 模式 XX` into the new format (keep the body and numbering semantics) | The "defect → gate conversion rate" denominator becomes 0 (**metric uncomputable**; gates unaffected) |

**Non-blocking change (migration optional)**: `docs/B/` document numbers shifted by one (`B-03`→`B-04`, `B-04`→`B-05`, `B-05`→`B-06`, `B-06`→`B-07`), and the red-line authority table takes the new number `B-00`. Existing projects can follow their own index.

**Upgrade commands**:

```bash
npx skills update project-blueprint          # installed via skills.sh
dsh plugin --profile web add 'github:shuguang1994/project-blueprint#v2.0.0'   # installed via DSH
```

## 5. How to Verify (You Can Reproduce This)

This release does not conclude with "should be fine". **You can verify it yourself with 3 empty projects**:

| Step | Do this |
|------|---------|
| 1 | In a temp dir, create 3 minimal projects: ① Node + a test framework installed + test files; ② Node + **no test framework at all**; ③ docs-only (no source dir, no dependency manifest) |
| 2 | For each, say "initialize this project's development standards" and let the full initialization run |
| 3 | Check the artifacts as follows |

| Check | Expected |
|-------|----------|
| Full-text search for `passWithNoTests` | **0 hits** |
| Does the generated workflow call the gate entry? | **Yes** — a `scripts/verify.` call |
| Every job's first command | Contains `command -v` + a version print |
| Test step (shape ①) | **Present** |
| Test step (shape ②) | **Absent**, and `docs/B/B-03-测试指南.md` records the add-step contract |
| Drift check output on shape ③ | Contains "**不适用｜原因｜风险｜裁定**" or "切换为回退模式｜原因｜替代判据" — **not** a bare "skipping" |

**Negative verification** (confirm the checks actually block, rather than only saying nice things) — try any one:

| Problem you introduce | Expected to be caught |
|-----------------------|-----------------------|
| Add a `blocking` red line with no gate to the authority table | "**A red line exists with no gate**" error |
| Point a `source` at a non-existent ID | "References a non-existent ID" error |
| Delete the CI test step (shape ①, which does have tests) | `warning`: "tests were built but never wired into CI" |

## 6. Known Boundaries (Stated Honestly)

| Boundary | Note |
|----------|------|
| End-to-end verification this round covered Node (with/without tests) and docs-only | The gate inlining, runtime self-verification and test-step rules for the Go / Vue / React / Python workflows **are in place and pass syntax-level checks**, but were not each run end-to-end on a real project this round |
| The authority table is "optional but strongly recommended" | Without it the two-way check degrades to one-way (stated explicitly); it does not raise false errors |
| The fallback comparison's direction one is `info` level | "A directory exists but is not in the module table" only informs on projects with no source root — top-level dirs include tools/docs, so a `warning` would spam |
